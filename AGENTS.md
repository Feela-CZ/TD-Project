# Work and Codex handoff

At the start of a new task, identify the checked-out branch and commit and read [WORK-HANDOFF.md](WORK-HANDOFF.md) from the `work-handoff` branch. Review the latest Git history and inspect the current implementation before relying on earlier observations. Apply the project's current constraints and the user's latest instructions.

- Use the `work-handoff` branch for coordination. Base code changes on the relevant current source branch, using a separate task branch. Record its commit or pull request in the handoff.
- When the user asks to hand off work, update the existing `WORK-HANDOFF.md` on `work-handoff`. Record the inspected revision, task and approval state, next action, checks actually run and their results, blockers, and links to evidence. Check for a newer handoff before writing.
- Keep public repository notes limited to project information suitable for publication. Use an approved private channel for private context, unpublished assets, personal data, and credentials.
- Use the repository and its recorded checks to continue from Work web, Codex Cloud, or a local Codex checkout. Ask for a local file only when the task needs something GitHub does not contain.
